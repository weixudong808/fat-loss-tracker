# Cron 定时任务 Prompt 模板

使用前把 `<URL>` 替换成 scripts/config.json 里的 spreadsheet_url；开头"本次请求是由…触发的"必须保留。

通用红线：只输出给用户看的消息本身，第一句就是正文；禁止出现"正在读取/核对表格"等内部过程；像发微信；不说教不套路。

---

## 1. 每日早安简报（建议 08:00，cron `0 8 * * *`）

```
本次请求是由「减脂早安简报」定时任务到时触发的。
现在是早上8点，按 fat-loss-tracker skill 生成今日减脂早安简报。全程静默执行，用 lark-cli sheets +csv-get 读飞书电子表格（URL: <URL>）：
1. 读「用户档案」A1:T2：碳水g/蛋白g/脂肪g、当前档位kg、训练日安排、记忆备注；
2. 执行 `date +%u` 取今天星期数（1=周一…7=周日），对照「训练日安排」判断今天是否训练日；
3. 读「体重记录」「饮食记录」「训练记录」A1:H200，核对昨天：体重称了没、三餐记了几顿、练没练；
4. 读「训练记录」A1:H200，筛今天日期且状态=待完成的行（=今天的训练计划；已完成=历史）。
然后输出简报，按序：
- 昨日回顾：记了的一句带过，缺的轻点一句
- 今天是否训练日：有待完成计划→逐动作报「主题：动作 重量kg×组数×次数」；训练日无计划→提示练完直接报你自动排；非训练日→一句休息恢复
- 称重提醒：昨天没称才提醒，称过不重复
- 今日饮食计划：碳水Xg/蛋白Xg/脂肪Xg（必须用档案值）
- 结尾多问一嘴：今天打算吃哪几类食物
风格：真实直接、像朋友、不说教；≤6行/160字。
输出红线：只输出简报正文，第一句就是跟用户说的话；禁止输出读取/核对过程。直接输出简报内容即可。
【后续对话规则】用户回复想吃的食物种类后：按档案碳水/蛋白/脂肪目标给2-3种搭配方案，每种写清食材克数并逐项加总对照（每项±10g内达标，不达标先调份量）。
```

## 2. 三餐提醒（【】替换餐次）

| 任务 | cron |
|---|---|
| 早餐记录提醒 | `30 9 * * *` |
| 午餐记录提醒 | `30 12 * * *` |
| 晚餐记录提醒 | `0 19 * * *` |

```
本次请求是由「【餐次】记录提醒」定时任务到时触发的。
按 fat-loss-tracker skill 做【餐次】记录提醒。全程静默：用 lark-cli sheets +csv-get 读「饮食记录」（URL: <URL>，范围 A1:D200），核对今天有没有餐次=【餐次】的行。
- 没记 → 轻松问一句这餐吃了什么，≤2句；
- 已记 → 不提醒不追问，只回半句确认。
风格：像朋友随口一问，不说教、无套路。
输出红线：只输出消息本身，第一句就是正文，禁止暴露读表过程。直接输出消息内容即可。
```
